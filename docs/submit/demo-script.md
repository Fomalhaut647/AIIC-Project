## 0:00-0:20 wow moment（作弊模式）

### 画面操作

- 视频开始即在 view-interview 三栏 layout
- 主对话区已可见前 1-2 轮上下文（用户已介绍 Formulock 核心架构：解析 Excel/发票/PDF 凭证 + AI 生成公式 + 本地引擎核算）
- Interviewer 抛新追问，TTS 自动朗读 + 主对话区文字渲染

### Interviewer 提问（TTS 朗读 + 渲染）

> 你说 AI 仅基于报表结构生成公式，Excel 数值绝不出本地。但很多公式逻辑依赖具体数据特征——比如 SUMIF 的条件值、INDEX/MATCH 的查找边界。AI 没看过实际数值，怎么保证公式逻辑正确？

### 用户输入框（故意制造紧张）

- 光标闪烁
- 敲入 "我想想..." 然后 Backspace 删掉
- 静止 3 秒

### 右侧 OS panel（打字机效果实时滚出）

```
[Coach 内心 OS]

- Reviewer 在质疑你隐私边界 vs 公式正确性的可行性
- 建议两层回答：
  1. schema 信息通常已够：财务报表强结构化、公式模板化
     （SUMIF 按科目代码聚合 → 科目代码是 schema 不是数据）
  2. 必要时用 column-level summary（enum 集合 / 数值范围）
     作脱敏 hint，仍不暴露行级数据
- 举具体例子：附注披露的"前五大客户"用 TOP-N 聚合 schema 描述
```

### 旁白（0:08-0:20，约 12s）

> 这是 Coach 在背后给我递推理线索。Interviewer 装作不懂我的项目，让我练习把它讲清楚；Coach 懂我的全部材料，在我卡壳时帮我找思路。这是 ChatGPT 同 session 做不到的——它没法同时扮演两个信息不对称的角色。

### 结尾

- 0:18-0:20：用户开始打字 "我会从两层回答..."（敲键盘音效，制造"得到提示后回到答题"的连续感）

## 0:20-0:50 用户与痛点（30s）

### 画面

- 切换到一张访谈记录页面（5 个对话片段并排截图）
- 高亮三个 quote 黄底：
  - "感觉模拟面试肯定有用，能防止怯场"（5/5 同意）
  - "这种产品我可能不会用？我也说不上为什么"（3/5 不愿试）
  - "你直接帮我练就行了，我也不知道我缺什么"（说不出具体需求）

### 旁白（30s）

> 我访谈了 5 个准备保研复试或大厂实习面试的本科生。结果有点反直觉：所有人都觉得模拟面试有价值能防止怯场，但只有 2 个人愿意真试这种产品，而这 2 个人也说不出具体需要什么。
>
> 这个结果驱动了我整个产品哲学：与其调研用户能描述出来的需求，不如做一个让人体验后立刻被惊艳的具体能力——一种 ChatGPT 给不了的、第一次看到就让人意识到"原来这才是我需要的"东西。

## 0:50-2:00 核心闭环演示（70s）

分 5 段快剪。每段操作流畅、旁白同步贴在画面上。

### (a) 0:50-1:00 上传 PDF + STT 一句话讲项目（10s）

**操作**：
- 在 view-onboarding 阶段
- 点 "📎 上传项目材料" → 选示范 PDF 简历 → 进度条 1s 完成 → 解析回填 textarea
- 切到 "讲讲你的项目" 阶段，点 mic 按钮 → 红色 pulse → 用户语音说："我做了一个叫 Formulock 的 AI 财务助理，处理 Excel 报表的合并和披露生成"
- 文字实时落入 textarea

**旁白**：
> 上传简历 PDF 自动解析；麦克风一句话讲项目，自动落到面试材料。

### (b) 1:00-1:20 进入面试 + TTS 朗读 + 语音回答（20s）

**操作**：
- 提交 onboarding，view-interview 加载
- speaker 图标 on，Interviewer 第一题 TTS 自动朗读："你这个项目最有挑战的部分是什么？"
- 用户点 mic → 语音回答："最有挑战的是隐私边界设计..."

**旁白**：
> 听面试官读题、用语音回答——和真实面试一样的节奏。文字、语音、上传文件全部独立 toggle，用户自己控制。

### (c) 1:20-1:35 OS panel 持续提示（强调作弊模式不止开场）（15s）

**操作**：
- Interviewer 追问"那如果客户要求百毫秒级响应..."
- OS panel 滚出新一轮提示
- 用户按提示回答

**旁白**：
> 作弊模式不是只有开场那次——整轮面试 Coach 一直在背后帮你，直到你每个阶段的弱点 slot 都暴露出来。

### (d) 1:35-1:50 报告页 + 简历多轮迭代（15s）

**操作**：
- 点击"结束面试"按钮，跳到 view-report
- 显示：4 个弱点 slot（baseline/clarification/technical_depth/scenario_challenge）+ recurring_weaknesses 累计统计 + 简历改写左原右改对比
- 用户在第二个 textarea 输入改写后的版本，点"让 Coach 看看"
- 弹出第二轮 Coach 反馈

**旁白**：
> 复盘报告给量化弱点 + 简历改写。改完还能让 Coach 再看一轮，不限轮次直到收敛。

### (e) 1:50-2:00 dashboard + 一键重练（10s）

**操作**：
- 点"我的训练"按钮 → view-profile
- 时间线显示历史 sessions + 累计 hero stats
- 点某历史 session 的"重练 baseline"按钮
- 弹出 mini-report modal，跑完 2 分钟单 slot 训练

**旁白**：
> 跨 session 长期训练——每次重练只针对单弱点 slot，2 分钟完成。这是 ChatGPT 单 session 没法做的。

## 2:00-2:40 设计取舍（40s）

### 画面

- 切到 6 个并列方块（半透明黑底白字盖在产品 UI 上）
- 上 3 块 "刻意做的"，下 3 块 "刻意不做的"
- 每块 5-6s 切入，有 motion

### 旁白（40s，~120 字）

> 三件刻意做的：
>
> 一、双 Agent 信息不对称——Coach 懂你 / Interviewer 装作不懂你，强制你练把项目讲清楚
>
> 二、状态机六阶段——从介绍到追问到挑战层层递进，不是无限循环聊天
>
> 三、作弊模式——刚才你看到的 OS panel
>
> 三件刻意不做的：
>
> 一、账号登录系统——anonymous + localStorage 是设计意图，让用户 5 秒开始练，不在产品入口砸 30 秒
>
> 二、SQLite 数据库——这是 mock 工具不是数据库系统，每次 session 是 self-contained
>
> 三、多面试官 panel——会稀释双 Agent 的信息不对称设计哲学，刻意不做
